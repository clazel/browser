# clazel-encoding

The WHATWG Encoding Standard's labels, hooks and decoders, formally verified
with Verus. Part of [Clazel](../../README.md), a web browser built from the
bottom up by AI using formal verification instead of trust.

## What it is

An implementation of the WHATWG Encoding Standard (Living Standard, commit
`dd79434`, 19 October 2026):

- encodings, names and labels, and "get an encoding" (section 4.2), over
  the standard's own `encodings.json`;
- the hooks "BOM sniff" and "decode" (section 6), and UTF-8's hooks;
- the decoders of UTF-8 (8.1), the 28 single-byte encodings (9, with their
  encoder), replacement (14.1), UTF-16BE and UTF-16LE (14.2 to 14.4) and
  x-user-defined (14.5), over the standard's `indexes.json`.

Decoders take the whole input (no streaming) and return code points as
`u32`; every one is a Unicode scalar value (proven). "Decode" returns
`None` for the seven multi-byte encodings, whose decoders are not written
yet (Phase 4 item 4.4), so a caller can say so instead of guessing.

The tables are generated by `cargo xtask tables` from the vendored
`data/encoding-dd794344/` (`encodings.json`, `indexes.json`), and `cargo
xtask check` fails if a generated table differs from that data. The
single-byte indexes are also checked against a second body's tables, the
Unicode Consortium's mapping files (`data/unicode-mappings/`), with every
difference listed there.

Not included: the multi-byte decoders (item 4.4), encoders other than UTF-8
and single-byte, streaming and the `TextDecoder` API.

## Verification

Tier 2: the implementation is proven functionally correct against an
executable specification, with Verus. Verus also proves that it never
panics, overflows or indexes out of bounds. See the
[tiers](../../docs/VERIFICATION.md#tiers).

- Every exec function is proven equal to a step-by-step transcription of
  the standard (`src/*/spec.rs`).
- Lemmas: every label maps to exactly one encoding, and "get an encoding" of
  an encoding's own name is itself (`labels/lemmas.rs`); a single-byte
  decoder never emits a surrogate, is injective on the bytes its index
  defines, and its encoder inverts it (`single_byte/lemmas.rs`, on facts
  about the generated indexes proven by evaluating them in
  `single_byte/tables.rs`); the UTF-16 decoder emits only scalar values
  (`utf16/lemmas.rs`).
- Independent transcriptions proven equal to the spec on every input:
  UTF-8 from the Unicode Standard chapter 3; same-text second readings of
  "get an encoding", "BOM sniff" and "decode", the single-byte decoder and
  encoder, UTF-16 (with "restore" done literally on the queue, which checks
  the spec's modelling of it), replacement and x-user-defined.
- Every mutation listed in `mutations.json` is certified as caught by a proof
  that Verus checks: each step of each algorithm, and a duplicated entry in
  each generated index and in the labels table.
- Conformance: WPT `encoding/` (UTF-8 decode cases; every label; the
  single-byte decoder for every label; fatal single-byte decoding of every
  byte; UTF-16 surrogates), and differential tests against
  `str::from_utf8_lossy`, `str::from_utf8` and `encoding_rs` (Firefox's):
  label resolution, "decode" with BOM sniffing and fatal decoding for every
  encoding with a decoder, and the single-byte encoder, on random inputs.

Modelling choices are listed at the top of each `spec.rs`: I/O queues are
a sequence plus a read position; "restore" is not advancing (or, for
UTF-16, moving back to) the position; the tables come from the standard's
JSON files. The standard's "peek" reads from index 1, which is read here as
index 0 (see [docs/ERRATA.md](../../docs/ERRATA.md); reported upstream).

Current proof, mutation and conformance counts are in the
[status table](../../README.md#verification-status).

## Trust

The proofs assume the Rust compiler, Verus, and that the spec matches the
standard, which the conformance tests and the independent transcriptions
support but cannot prove. See the
[trusted computing base](../../docs/VERIFICATION.md#trusted-computing-base-what-we-do-not-prove).

## Usage

Not yet published to crates.io (the workspace sets `publish = false`, and
the version is `0.0.0`). Use it as a path dependency:

```toml
[dependencies]
clazel-encoding = { path = "crates/clazel-encoding" }
```

```rust
use clazel_encoding::labels::exec::get_an_encoding;
use clazel_encoding::labels::spec::Encoding;
use clazel_encoding::utf8::{
    decode::{decode, decode_without_bom_or_fail},
    encode::encode,
};

fn main() {
    // "Get an encoding": labels are ASCII case-insensitive, trimmed.
    let label: Vec<u32> = " Latin1 ".chars().map(u32::from).collect();
    assert_eq!(get_an_encoding(&label), Some(Encoding::Windows1252));

    // "Decode" with a fallback encoding (a byte order mark would win).
    let text = clazel_encoding::hooks::decode::decode(b"caf\xE9", Encoding::Windows1252);
    assert_eq!(text, Some(vec![0x63, 0x61, 0x66, 0xE9]));

    // Strips a leading BOM and replaces each error with U+FFFD.
    assert_eq!(decode(b"\xEF\xBB\xBFa\xFFb"), vec![0x61, 0xFFFD, 0x62]);

    // The fatal variant returns `None` on the first error.
    assert_eq!(decode_without_bom_or_fail(b"a\xFF"), None);

    // Encoding takes scalar values.
    assert_eq!(encode(&[0x61, 0xE9, 0x1F600]), "aé😀".as_bytes());
}
```
